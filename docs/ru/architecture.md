# Архитектура TaskMonad

`taskmonad` — это монадический фреймворк для конструирования пайплайнов и асинхронного выполнения задач в Python. Он объединяет парадигмы функционального программирования (монады, функторы, аппликативные ответвления/tap) с асинхронной экосистемой Python (`asyncio`) и настольными графическими интерфейсами (PyQt / PySide).

---

## 1. Базовые принципы

Классические асинхронные сценарии и скрипты в Python часто сталкиваются со следующими проблемами:
- **«Пирамида коллбэков» и вложенные блоки `try/except`**, затрудняющие чтение и сопровождение логики обработки ошибок.
- **Случайная мутация общего состояния**, когда параллельные шаги перезаписывают данные в общих словарях.
- **Зависание графического интерфейса пользователя (GUI)** и громоздкая ручная синхронизация потоков Qt с циклом событий asyncio.
- **Сложность декларативного конфигурирования**, когда пайплайн требуется загружать из внешних файлов (YAML/JSON).

TaskMonad решает эти проблемы за счет строгих математических и функциональных концепций, адаптированных для Python:

```
       [ Входная задача (Task) ]
                    │
               >> (bind)
                    ▼
     Возникла ли ошибка выше по цепочке?
        ├── ДА ──► Short-circuit (Мгновенный возврат Exception)
        └── НЕТ ─► Передача значения на следующий шаг (Task / Callable)
                         │
                    << (tap)
                         ▼
        Выполнение побочного эффекта (лог, очистка)
        Исходное значение передается дальше без изменений!
```

## 2. Концепция Монады в TaskMonad

Монада в TaskMonad инкапсулирована в обобщенном классе `Task[T]`. Он оборачивает асинхронное вычисление сигнатуры:

$$\text{Computation} : \text{TaskContext} \to \text{Coroutine}[\text{Tuple}[\text{TaskContext}, T \cup \text{Exception}]]$$

### 2.1 Три монадических закона

Библиотека `taskmonad` строго следует монадическим законам (Monad Laws), что гарантируется автоматическими тестами в `tests/test_taskmonad.py`:

#### 1. Левая идентичность (Left Identity)
Оборачивание значения в монаду с последующим связыванием функцией $f$ эквивалентно прямому применению $f$ к значению:
$$\text{Task.of}(x).\text{bind}(f) \equiv f(x)$$

```python
x = 10
f = lambda val: Task.of(val * 3)

res1 = await Task.of(x).bind(f).run()
res2 = await f(x).run()
assert res1[1] == res2[1] == 30
```

#### 2. Правая идентичность (Right Identity)
Связывание монады с единичным конструктором `Task.of` возвращает исходную монаду без изменений:
$$m.\text{bind}(\text{Task.of}) \equiv m$$

```python
m = Task.of(42)
res1 = await m.bind(Task.of).run()
res2 = await m.run()
assert res1[1] == res2[1] == 42
```

#### 3. Ассоциативность (Associativity)
Последовательное связывание не зависит от расстановки скобок в цепочке:
$$m.\text{bind}(f).\text{bind}(g) \equiv m.\text{bind}(\lambda x. f(x).\text{bind}(g))$$

```python
m = Task.of(5)
f = lambda x: Task.of(x + 10)
g = lambda x: Task.of(x * 2)

res1 = await (m.bind(f).bind(g)).run()
res2 = await m.bind(lambda x: f(x).bind(g)).run()
assert res1[1] == res2[1] == 30
```

## 3. Модель изоляции ошибок (Short-Circuiting)

Если какая-либо операция в пайплайне генерирует исключение или возвращает объект `Exception`, TaskMonad перехватывает его:

1. **Short-Circuiting (короткое замыкание)**: Все последующие шаги, подключенные через `bind` (`>>`), `map` или `tap` (`<<`), пропускаются без выполнения.
2. **Безопасность**: Исключение не приводит к аварийному падению процесса или потере контроля над циклом событий, а аккуратно возвращается в кортеже результата `(ctx, exception)`.
3. **Терминальные хуки**: Если для задачи был зарегистрирован хук `.error(hook)`, он будет вызван с аргументами `(exception, final_context)`.
4. **Оповещение интерфейса**: При запуске в `TaskRunnerThread` сигнал `failed` отправляет строку ошибки в главный поток UI.

```python
def failing_step(x):
    raise ValueError("Некорректные входные данные")

def unreachable_step(x):
    print("Этот код никогда не выполнится")
    return x * 2

task = Task.of(10) >> failing_step >> unreachable_step
ctx, result = await task.run()

assert isinstance(result, ValueError)
```

## 4. Иммутабельность состояния: `TaskContext`

`TaskContext` — это замороженный (frozen) датакласс, содержащий два изолированных пространства имен:

| Пространство | Глубокое копирование при изменении? | Назначение |
| :--- | :--- | :--- |
| `data` | **Да** (через `copy.deepcopy`) | Бизнес-данные, результаты вычислений, полезная нагрузка |
| `meta` | **Нет** (поверхностная копия `.copy()`) | Системные дескрипторы: коллбэки Qt сигналов, системные логгеры |

### Зачем нужно глубокое копирование `data`?
Потому что задачи могут исполняться конкурентно через `Task.parallel`. Глубокое копирование исключает ситуацию, при которой одна параллельная ветка модифицирует вложенный список или словарь другой параллельной ветки.

```python
ctx1 = TaskContext(data={"count": 1})
ctx2 = ctx1.set("count", 2)

assert ctx1.get("count") == 1
assert ctx2.get("count") == 2
assert ctx1 is not ctx2
```

## 5. Конкурентность и параллелизм

Метод `Task.parallel` запускает несколько задач параллельно через `asyncio.gather(*, return_exceptions=True)`.

- **Fail-Fast**: Если хотя бы одна подзадача завершилась ошибкой, пайплайн прерывается с возвратом первого возникшего исключения.
- **Объединение контекстов**: При успешном завершении всех параллельных ветвей их словари `data` объединяются в единый результирующий `TaskContext`, а результаты собираются в список `[val_1, val_2, ...]`.
- **Мониторинг каждого шага**: Каждая параллельная задача автоматически отправляет сигналы `"running"` и `"success"` / `"failure"` в UI.

## 6. Потокобезопасный мост Qt (Qt Signal Bridge)

Приложения с графическим интерфейсом на PyQt6, PyQt5 или PySide6 не должны блокировать главный UI-поток длительными сетевыми или вычислительными операциями.

Класс `TaskRunnerThread` наследуется от `QThread`:
1. Запускает отдельный фоновый поток операционной системы.
2. Создает изолированный цикл событий `asyncio`.
3. Внедряет функции обратного вызова `emit_step` и `emit_log` в `ctx.meta`.
4. Генерирует сигналы Qt через границы потоков (`started`, `step_executed`, `log`, `finished`, `failed`).
5. Корректно завершает и закрывает цикл событий при окончании работы.
